## Reporting a Vulnerability

We take the security of this project seriously. If you believe you have found a security vulnerability, please report it to us as described below.

**Please do not report security vulnerabilities through public GitHub issues.**

### How to Report

If you believe you have found a security vulnerability, please submit a report via email to **[INSERT_CONTACT_EMAIL_HERE]**.

In your report, please include:
* The type of issue (e.g., buffer overflow, SQL injection, cross-site scripting, etc.)
* Full paths to source file(s) related to the manifestation of the issue.
* The location of the affected source code (tag/branch/commit or direct URL).
* Any special configuration required to reproduce the issue.
* Step-by-step instructions to reproduce the issue.
* Proof-of-concept or exploit code (if possible).
* Impact of the issue, including how an attacker might exploit it.

### Response Timeline

* **Acknowledgment:** We will respond to your report within 48 hours to acknowledge receipt.
* **Assessment:** We will assess the vulnerability and determine its severity. We may contact you for further information.
* **Fix:** If the vulnerability is confirmed, we will work on a patch. We aim to release fixes for critical vulnerabilities as quickly as possible.
* **Disclosure:** We ask that you maintain confidentiality and do not disclose the vulnerability publicly until we have had a reasonable amount of time to address it (typically 90 days, unless a fix is released sooner).

We appreciate your efforts to responsibly disclose your findings and will make every effort to acknowledge your contributions.
